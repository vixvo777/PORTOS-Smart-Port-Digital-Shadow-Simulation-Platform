# PORTOS — Smart Port Digital Shadow (Cesium-restored frontend)

This is the integrated New Orleans frontend. The **Digital Shadow tab opens the same style of standalone CesiumJS Viewer used in the earlier project build** (`twin3d.html`): full globe/scene canvas, OpenStreetMap imagery, Cesium Animation widget, Cesium Timeline, Home View and Free Camera controls. It is not a MapLibre or Leaflet replacement.

## What is included

- Command Center, Vessel Traffic, Berth Planner, What-If Simulation and Analytics screens.
- A standalone CesiumJS 1.120 3D Digital Shadow at `/twin3d.html`, styled after the previous `twin3d(2).html` implementation.
- Actual New Orleans port boundary GeoJSON and 99 berth/stopping-cluster polygons, extruded in 3D.
- Cesium clock, Animation widget, Timeline scrubber, playback speed, Home View and Free Camera.
- Procedural cargo-vessel shapes (hull, bridge and deck containers) with smooth curved approach/departure paths, heading changes and berth stops.
- Historical playback from actual New Orleans port-call timestamps and stop locations.
- What-If mode calls the existing `/api/v1/scenarios/allocate` endpoint and shows scheduled queue waiting, berth assignment, service and departure states in Cesium.
- Vessel selection, berth status markers, layer toggles and live scene HUD.

## Data interpretation (important for your professor)

- Historical timestamps, stop coordinates and dwell durations are records from the New Orleans dataset.
- The published New Orleans tables do not contain continuous timestamped AIS tracks. Movement between port-call states is therefore illustrative; it is not claimed to be recovered AIS.
- The berth features are spatial stopping/berth-like clusters. Their spatial match is not a verified operational berth assignment or vessel-compatibility record.
- Historical port-call duration is dwell time, not measured anchorage queue waiting. What-If queue delay is generated by the allocation model and is labelled modelled.
- The current `optimized` backend policy is a deterministic greedy earliest-completion heuristic, not a globally optimal solver certificate.
- The 3D vessel geometry is procedural (hull, bridge and deck cargo boxes), not a detailed commercial vessel CAD model.
- The prototype is not a certified VTMS, route planner or navigation-safety tool.

## Requirements

- Windows 10/11
- Node.js 20+ and npm
- Existing Smart Port backend running at `http://127.0.0.1:8000`
- Internet access for CesiumJS CDN and OpenStreetMap tiles in the standalone Cesium view

## Install and run (Windows)

Keep this folder beside your existing `smartport_backend` folder; do not put it inside the backend.

**Terminal 1 — backend**

```bat
cd /d D:\SmartPort\smartport_backend
run_windows.bat
```

Check `http://127.0.0.1:8000/api/v1/health` before proceeding.

**Terminal 2 — frontend**

```bat
cd /d D:\SmartPort\smartport_phase2_complete_frontend
npm ci
npm run dev
```

Open `http://localhost:5173`. Click **Digital Shadow** in the left navigation to open the standalone Cesium scene. You can also open `http://localhost:5173/twin3d.html` directly.

If your backend uses a different address, open `twin3d.html?api=http://YOUR-HOST:8000` or set `VITE_API_BASE_URL` for the dashboard. The standalone Cesium page defaults to `http://127.0.0.1:8000`.

## Cesium controls

- Use the Cesium Animation widget in the lower-left corner to play/pause the simulation clock.
- Drag the Cesium Timeline along the bottom to scrub the selected date/horizon.
- Use the panel's playback-speed selector to change the clock multiplier.
- **Home View** returns to the New Orleans overview; **Free Camera** releases camera tracking.
- Click a ship to inspect its event, berth-cluster assignment, dwell or modelled waiting state.
- Layer toggles show/hide the port boundary, berth clusters, illustrative route lines and vessel labels.
- Switch to **What-If allocation**, adjust settings and press **Run What-If & show in Cesium**.

The scene renders a configurable sample of 80–220 vessels for laptop performance; the API and result metrics retain the full returned event set.

## Backend compatibility

The current frontend uses:

- `GET /api/v1/health`, `/overview`, `/map/port`, `/map/berths`, `/berths`, `/calls`
- `GET /api/v1/analytics/dwell`, `/analytics/berths`, `/analytics/timeline`
- `POST /api/v1/scenarios/allocate`

Use the `smartport_backend` folder included in this completion package. Its `app/main.py` contains the matching AIS analytics and scenario metric APIs. The startup scripts preserve an existing AIS table during a database rebuild and import the bundled AIS file if it is missing.

## Troubleshooting

- **API OFFLINE:** start the backend and check `http://127.0.0.1:8000/api/v1/health`.
- **CesiumJS failed to load:** check access to `cesium.com` and reload.
- **No map imagery:** check internet access to `tile.openstreetmap.org`.
- **Scenario fails:** check the chosen date is inside 2019 and the blocked berth IDs are valid IDs from the berth list.
- **Slow scene:** reduce Scene Density to 80 or 120 ships.
- **npm install fails:** Node/npm needs access to the npm registry; retry `npm install` once internet access is available.

## V3 standalone Cesium viewer with observed AIS

Open the Digital Shadow from the dashboard to launch `public/twin3d.html`.
This standalone CesiumJS page retains Cesium's Animation and Timeline widgets,
Home and Free Camera controls, layer toggles, historical/What-If controls,
and the original V3 panel layout. The page loads the included historical New Orleans AIS observations from `/api/v1/ais/coverage`, `/api/v1/ais/vessels`, and
`/api/v1/ais/track/{mmsi}`. The viewer defaults to 80 vessels for laptop performance and offers 200 or all 477 MMSIs as heavier options. Track segments are not connected across recorded segment boundaries or gaps over five minutes; Cesium samples positions only within each continuous segment. The source timezone is unspecified, so timestamps are mapped onto the Cesium UTC clock only as a display convention. In What-If mode, modeled scenario vessels remain a separate layer
from observed AIS. The What-If API reports modeled queue peak, per-berth and aggregate utilization, throughput, served/unserved vessels, completion time, delay distribution and a like-for-like policy comparison. Hypothetical expansion units are synthetic capacity assumptions.
